## Search Console「重复网页，用户未选定规范网页」修复

根因（按确定性排序）：
1. canonical 全靠客户端 JS 注入，`dist/index.html` 静态 HTML 里没有任何 `<link rel="canonical">`；
   Google 未执行 JS 时该 URL 就是「未指定 canonical」。
2. `updateHead.js` 原先用 `window.location.origin` + 原样 `to.path` 拼 canonical →
   netlify.app 子域 / 大小写 / 尾斜杠 / query 变体各自自指。
3. SPA 200 回退让任意 URL 都返回同一份 index.html，重复空间无收敛。

已改：
- 新增 `src/config/site.js`：`siteOrigin()`，可用 `VITE_SITE_ORIGIN` 覆盖，默认 `https://image.chobit.org`。
- 新增 `src/seo/canonicalPath.js`：大小写／尾斜杠／重复斜杠／query&hash／非法 locale 收敛到 `/{locale}/{slug}`；
  非白名单深路径保留自指（交给路由的 noindex）。
- `src/seo/updateHead.js`：canonical 与 9 个 hreflang alternate 全部走统一来源 + 规范化路径
  （hreflang 复用 canonical 的 tail，保证 9 语种严格指向同一资源）。
- `scripts/generate-sitemap.mjs`：origin 改用 `siteOrigin()`，与 canonical/robots 同源。
- 新增 `tests/canonicalPath.test.mjs`（12 条）。

门禁（本轮全绿）：`npm test` 40/40；`vite build` ✓（仅 chunk>500kB 告警）；
`check:i18n` 9 语言 × 224 key ✓；产物含 `dist/_redirects` ✓。

新增文件：
- `netlify/edge-functions/seo-canonical.js`：边缘层三件事 ——
  ① host/协议/路径不一致 → 301 收敛（`image.chobit.org` 为唯一主域；netlify.app 默认子域归到主域；
     `deploy-preview-*--*`、`*-branch--*` 子域与 localhost 豁免，避免打挂预览环境与本地 CLI）；

     等于把整批无效 URL 声明成首页重复项，比原问题更严重，已修）。

- `tests/netlifySeoCanonical.test.mjs`：24 条，含与 `src/config/tools.js`、`localeConfig.js` 的清单一致性断言
  （Edge Function 的 slug/locale/hreflang 清单是硬编码的，靠此测试防漂移）。

保留 `public/_redirects`：Edge Function 把根路径 `/` 判为 passthrough，仍需它做 SPA 回退供客户端语言探测跳转。
