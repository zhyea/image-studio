## 任务：修复预存 lang/title 串位 bug（用户指令「修」）

### 根因（已源码确认）
- vite-ssg 默认 `concurrency = 20`（node_modules/vite-ssg/.../vite-ssg.D5Fdxh1E.mjs:1372），即 20 路由并发预渲染。

- `vite.config.js` `onBeforePageRender`：删掉此前误用 `appCtx.app.config.globalProperties.$i18n.global.locale`
  （$i18n 是 Composer 无 `.global`，导致 `reading 'locale'` 构建报错），仅保留**按路由路径确定性改写 `<html lang/dir>`**，与 @unhead 双保险。

## 任务：用极简自研 i18n 替换 vue-i18n（robin「换」）

### 动机（实测）
- vue-i18n 运行时 100KB raw / **33.5KB gz**，占单页初始 JS 约 21%；而项目实际只用 `t()`、`locale`、1 处插值。
- 故保留 9 语种、仅替换库，不必砍多语言（砍掉只多省 ~6KB gz，却要 −105 个 SEO 页面）。

### 改动
- `src/i18n/index.js` 重写：`useI18n()`（drop-in，返回 { t, locale }）、`createI18nInstance(locale)`、
  `loadLocaleMessages`、`I18N_KEY`；内部 `createComposer` + `resolvePath` + `{name}` 插值 + en/zh 兜底。
  **用 `shallowRef` 存 messages**（避免为 224 键字典逐层建深层响应式代理；setLocaleMessage 整体替换 .value 触发更新）。
- `src/main.js`：`app.use(i18n)` → `app.provide(I18N_KEY, i18n)`；beforeEach 去掉 `.global`（改用 `i18n.locale.value` / `i18n.get|setLocaleMessage`）。
- 10 个文件的 `import { useI18n } from 'vue-i18n'` 改为自建模块（App.vue→'./i18n'；其余→'../i18n'）。
  App.vue/组件/视图的 `t('...')` 调用点**一处未动**（112 处）。
- `src/seo/headConfig.js`：删掉对已失效 vue-i18n 类型的 JSDoc，简化为 `const t = i18n.t.bind(i18n)`。
